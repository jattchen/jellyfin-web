## 挂接

同一个输入框服务名称搜索和画面片段，但输入本身不发请求，也不改地址。`draft` 是本地 `useState(query)`，`onSearch` 只改草稿。按钮或回车（中文选词回车除外）把去掉首尾空白的文字写入 URL 的 `query`，并让草稿与这个已提交文字对齐。刷新或从原生播放返回时，页面用地址里的已提交文字恢复两个结果，不靠一个空的本地状态。

`SearchResults` 仍用原来的接口、权限和筛选。`collectionType` 与页面上的 `parentId` 只交给名称搜索。已提交文字为空时显示原来的搜索建议，不出现「名称搜索」。提交后名称搜索和画面片段同时在页面上，但不是同一块结果。名称搜索可以是官方的没有结果，下面仍可以有片段。

画面区域收到的是已提交的 `query` 和页面上的 `parentId`，不传 `collectionType`。草稿和已提交文字不同时，保留上次片段并标明还没提交。草稿变化不会清掉上一轮片段，也不会另起一次请求。

## 接口

前缀 `/EmbeddingVideoSearch/v1/`，`apiVersion` 必须是 `"1"`，`ticksPerSecond` 必须是 `10000000`。

- `GET capabilities`
- `POST search`，正文只有 `query`、`limit`（3）、`clientQueryId`，以及页面上的 `parentId`（有的话）
- `GET segments/{segmentId}`

`parentId` 按页面上的官方形式原样送出（通常是不带连字符的 N）。不放进 `libraryIds`，也不传 `userId`。库、系列或季都交给插件判断。

`collectionType` 仍只作用于原来的标题搜索。插件请求里没有这个字段。

点击后先取片段详情。详情里的 `score` 固定为 0，因为这一步不再算相似度。网页保留搜索结果上的原分数，不拿它和详情分数比较，也不把分数显示成概率。核对只看影片身份、片段身份、媒体源字符串和时间窗。

影片身份接受官方 N 和插件 D：校验是合法的 N 或 D，去掉连字符后按小写比较。媒体源按原文比较，不是 GUID 就不把它当成 GUID。

详情失效时：`404` / `409`，`error.code` 为 `stale` 或 `incompatible`。这时不调用播放。页面上不解释音画是不是分开识别的；结果来自一段合在一起的画面和对白，技术上的表示是 `jointAudioVideo`。

条目详情的分数固定为 0。网页保留搜索当时的分数，核对时不比较分数。

官方条目若返回 401、403 或 404，这部片子的片段会从这块区域拿掉，不再用占位片名留着。加载超时或网络失败不会被说成没有结果，并可以重试。重试仍用原来的查询文字，会取消上一次还没结束的请求，并重新折上「可能相关」。标题搜索不受影响。

更换查询或页面上的 `parentId` 时，还没调用播放器的准备会被取消，迟到的结果也不会写到新查询上。已经开始的播放不会被停掉。退出、换用户或组件卸下时同样不会把迟到的播放发出去。

播放仍用现有的 `playbackManager.play`，显式传入 `startPositionTicks` 和 `mediaSourceId`，不传结束时间，所以不会在窗口结束时停下。

## 认证

只用当前 `useApi()` 的 `api.axiosInstance`、`api.getUri` 和 `api.authorizationHeader`。请求头是 `Authorization`。地址和日志里不放令牌，图片地址如果带 `api_key` 或 `Token` 就不会去取。条目和图片走官方接口，用户 id 只用当前登录用户。

结果只放在这个区域的状态里。换查询、退出、换用户或换服务器时清空，不用跨用户缓存。

## 测试

`embeddingVideoSearch.test.ts` 有 22 项，`items.test.ts` 有 2 项。都用假传输或假条目接口，不连接真实服务器，也不调用模型。

这 22 项碰到的控制包括：迟到结果不写进新查询、身份和媒体源按字符串核对、版本和 tick 不匹配、页面上的 `parentId` 原样送出且不进地址和日志、相关结果最多留 3 条、缺插件、详情分数不拿来和搜索分数比、播放只带起点和指定媒体源、过期或不兼容片段不播放、换查询或范围时取消还没发出的播放、重试时弱结果折叠收起、官方条目撤走后从这块区域移除。另外 2 项是官方条目请求：带上条目超时，并把 401、403、404 当成看不到；元数据超时不会被说成没有这部片子。

网络失败、正忙（HTTP 429，或可用性 `queueFull`）和一次查找传输超时，代码里有分支，但这 24 项没有把它们走成页面文案。超时相关的假测试只断言「超时问题可以重试」，以及条目元数据超时不当成没有结果。弱结果折叠收起有假测试；现场弱结果还没记成通过。

假测试不能代表现场每一次回调。排序质量、整库有没有覆盖、预处理能不能逐字对上，都不在这里。模型质量门槛还没过。不要把这个网页挂接写成整项功能已经验收完成。
